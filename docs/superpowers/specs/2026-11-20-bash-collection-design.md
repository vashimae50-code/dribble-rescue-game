# ドリバト バッシュコレクション 設計メモ（2026-11-20 rev2）

> rev2：ふつうのプレイではキャラが3Dではなく絵（スプライト）で出ていることが分かったので、絵のくつの色を変える 5-4 を足した

## 1. ねらい
- 【事実】前橋さんの要望（2026-11-20 チャット）：ボールと同じように、コインがたまったら買えるバッシュのコレクションを作る。デザインは参考画像12枚（ネオン単色、パステル、白黒ハイカット、つやありの赤黒、柄もの、左右で色がちがうものなど）を参考にする。左右で色がちがうバッシュを2種類くらい入れる
- 【事実】見え方の要望：買う画面（ショップ・図鑑）では細かく見られる。ゲーム中はざっくり色が変わるくらいでよい。買ったバッシュはプレイ中のキャラにはかせる（A案を選択）
- 【意見】ねらいは「コインを使う先」と「集めたくなる目標」を増やすこと。ボールと同じ遊び方にそろえて、子どもが迷わないようにする

## 2. やること／やらないこと
やること
- ラインナップ14足（ショップ13足＋ひみつ1足）をデータで持つ
- ショップに「👟 バッシュ」の棚を足す。買う・つかう、はボールと同じ操作
- 図鑑に「バッシュ」の段を足す（もっていないものはシルエット＋ねだん）
- プレイ中のキャラの くつの色を、えらんだバッシュの色にする（左右べつ）
- ぜんぶ集めると、ひみつの「ゴールド」がもらえる＋しょうごう

やらないこと
- 実在ブランドのロゴ・マーク・形のまね（ナイキのスウッシュ、ジャンプマン、コンバースの星、アシックスのライン、Li-Ningのマークなど）。サイドのマークはドリバトのボールのマークにする
- バッシュで能力が上がる、などのゲームの有利・不利（見た目だけ）
- 敵キャラのくつは変えない
- ゲーム中のくつの柄（炎・水玉など）の再現。ゲーム中は3色まで

失敗とみなすこと
- 買ったのにプレイ中に色が変わらない／左右ちがいが片方だけしか見えない
- 前からあるセーブデータで遊べなくなる、コインやボールが消える

## 3. 作り方の候補と決めたこと
| 案 | 中身 | よい点 | 弱い点 |
|---|---|---|---|
| ① コードで形・データで色（採用） | ショップの絵はデータからSVGで自動で描く。ゲーム中はキャラのくつ部分の色をデータの3色で塗りかえる | 1足ふやすのがデータ1行。左右ちがいも簡単。8人のキャラ全員に効く | 形はデフォルメのくつ1種類 |
| ② Meshyで1足作って部品ごとに塗りかえ | 3Dのくつを1つ作り、Blenderで部品に分ける | 見た目が本物に近い | Blenderで部品に分ける作業が重い |
| ③ デザインごとにMeshyで作る | 1足ずつ3Dを作る | いちばんリッチ | 20足では作業とファイルが重い |

- 【事実】前橋さんが①で了承（2026-11-20「よろしく」）。ショップの見本絵（14足）を見て「いいね」で了承
- 【提案】ショップの絵を描く部分だけ別ファイルにして、あとで②に差しかえられるようにしておく

## 4. 今のゲームのつくり（さわるところ）
- 【事実】`js/data.js`：`BALLS`（なまえ・ねだん・柄・色）、`SHOP_BALLS`、`ballComplete()`（ぜんぶ集めたらダイヤ）、`SUITS`、`newPlayer()`（`balls: ['std'], ball: 'std'`）、`TITLES`（`ball10`・`ballall`）
- 【事実】`js/main.js`：`shop()`（ボールの棚・`item()`）、図鑑（`zukan`）、`buy`（`d.kind === 'ball' ? BALLS : SUITS`）、`look = { suit, ball, ... }` をシーンに渡している
- 【事実】`js/scene.js`：プレイヤーは `makeHuman(o.human, suit, { ..., shoe: '#122a65', trim: '#ffd200' })`、敵は `shoe: '#22222a'`
- 【事実】`js/character.js` `makeHuman()` には見た目が2とおりある
  - 旧モデル（ボーン塗り分け）：`regionOf()` で Foot/Toe の骨とすねの下のほう（y<0.2）を `SHOE`、足の y 0.085〜0.12 を `TRIM` で塗る。左右・ソールの区別はない
  - 新モデル（`nativeLook`、Meshy＋Mixamo の GLB）：GLB の色・テクスチャをそのまま使う。くつの色は絵に焼き込み
- 【事実】`player()` は古いセーブに新しい項目を足す処理を持っていない（`newPlayer()` でだけ初期値が入る）
- 【事実】ふつうのプレイ（`?character3d=1` や `/preview/` でないとき）は、プレイヤーを3Dモデルではなく後ろ姿の絵（`img/player/n_*.webp`（男の子・3×3コマ）、`g_*.webp`（女の子・3×2コマ））で出している（`scene.js` 51〜53行・239行、`setMainVisible(false)`）。3Dモデルはお手本の小窓と3D試験版で使う
- 【事実】絵のくつは黒っぽい色で、コマの下から約13％の高さまでに入っている（`n_nrmR.webp` を測った）。左右の向きの絵は別の絵で、反転はしていない（`T.repeat` は正の値）

## 5. 設計
### 5-1. データ（`js/data.js`）
```js
export const SHOES = [ { id, n, cost, cut: 'low'|'mid'|'high', pat, cols, up, toe, heel, line, lace, sole, out, lining, tab, emb, embLine, window, stripe, solePat, L: {...}, R: {...}, secret } , ... ];
export const SHOP_SHOES = SHOES.filter((s) => !s.secret);
export function shoeComplete(p) { /* ballComplete と同じ。ぜんぶ持ったら 'gold' を足して true */ }
export const shoeSide = (s, side) => ({ ...s, ...(s[side] || {}) }); // 'L' | 'R'
```
- ゲーム中に使うのは各足の `up`（本体）・`sole`（ソール）・`line`（ライン）の3色だけ
- ラインナップと色は見本の `lineup.mjs` のとおり（下の表）。ねだんはボール（60〜500）に合わせた

| id | なまえ | カット | 🪙 | 元にした参考 |
|---|---|---|---|---|
| std | スタンダード（キャラのもとのくつ） | mid | 0 | 今のNo.7のくつ |
| lime | ネオンライム | low | 100 | 1枚目 |
| sakura | さくらピンク | low | 120 | 2枚目 |
| panda | パンダ | high | 150 | 3枚目 |
| redblk | レッド×ブラック（つや） | low | 180 | 4枚目 |
| allred | オールレッド | mid | 180 | 12枚目 |
| classic | クラシックホワイト | high | 200 | 11枚目 |
| royal | ロイヤルブルー | low | 220 | 6枚目 |
| fire | ファイヤー | mid | 300 | 8枚目 |
| confetti | コンフェッティ | low | 320 | 5枚目 |
| splash | ペイントスプラッシュ | low | 380 | 7枚目 |
| lrRB | ひだりみぎ レッド／ブルー | low | 420 | 9枚目 |
| lrLP | ひだりみぎ ライム／ピンク | low | 450 | 10枚目 |
| gold | ゴールド（ひみつ） | mid | — | ぜんぶ集めると |

- セーブ：`newPlayer()` に `shoes: ['std'], shoe: 'std'`。`player()` で古いセーブに `p.shoes ||= ['std']; p.shoe ||= 'std'` を足す
- しょうごう：`shoe5`（バッシュを5そく あつめる）、`shoeall`（ぜんぶ あつめる）。【提案】ボールの `ball10`／`ballall` に合わせる

### 5-2. ショップ・図鑑の絵（新ファイル `js/shoes.js`）
- 見本の `docs/superpowers/specs/bash-collection/shoes-art.mjs` の `shoeSVG(d, size)` をそのまま移す。SVG文字列を `data:image/svg+xml` にして `<img>` で出す（`ballIcon()` と同じ使い方、id ごとにキャッシュ）
- 左右ちがい（`L`/`R` がある）は2足を重ねて描く。それ以外は1足
- ショップの棚：ボールの棚と同じ `item()` の形。アイコンはボールより横長なので、バッシュ用のクラス（例 `.sw.shoe`、横長）を足す
- 図鑑：もっていないものは絵をうすく（`dim`）＋「？？？」＋ねだん。ひみつは「👟 ？？？ ぜんぶ あつめると…」
- 文字はひらがな中心（低学年向けの方針）

### 5-3. ゲーム中のくつの色（`js/character.js` / `js/scene.js` / `js/main.js`）
- `main.js` の `look` に `shoe: SHOES.find((x) => x.id === p.shoe)` を足し、`scene.js` で `makeHuman(..., { shoeL: {up, sole, line}, shoeR: {...} })` を渡す（`opt.shoe` は敵用に残す）
- 旧モデル：`regionOf()` で骨の名前の Left/Right を見て左右の色を選ぶ。足の下のほう（ソール）は `sole`、今 `TRIM` にしている帯は `line`、それ以外は `up`
- 新モデル（GLB）：くつの部分だけ色を上書きする
  - 読み込み時、頂点ごとにいちばん重い骨が `LeftFoot/LeftToeBase`（とすねの下のほう）なら左、Right なら右、という印（頂点属性 `shoeSide`、0/1/2）と、足うらからの高さを持たせる
  - `MeshToonMaterial` の `onBeforeCompile` で、印がある所はテクスチャの色の代わりに、高さに応じて sole／line／up の色を使う
### 5-4. ふつうのプレイの絵（スプライト）のくつの色（`js/scene.js`）
- プレイヤーの `SpriteMaterial` の `onBeforeCompile` で、コマの中の位置（`fract(vMapUv * vec2(3, PSROWS))`）が下から一定の高さ以内で、色が暗いところを、くつの `up` の色にする。明るさは元の絵の濃淡を残す
- コマの左半分＝左足、右半分＝右足（後ろ姿なので画面の左がキャラの左足）
- `std` のときは何もしない（今の絵のまま）
- 高さのしきい値・暗さのしきい値は、男の子・女の子の絵でそれぞれ見て決める（男の子は約0.135）

- `std`（スタンダード）は「そのキャラのもとのくつのまま（色を上書きしない）」とする。【提案】キャラ選択で8人になったとき、紺のくつが他のキャラのユニフォームと合わないのを避けるため。ショップの絵は No.7 の紺×黄で描く

## 6. 作る人にまかせること
- ソール・ライン・本体を分ける高さのしきい値（旧モデルと GLB で足うらの高さがちがう。GLB は足うら y≈-0.95 と `character.js` のコメントにある）。実際の画面で見て決める
- 新モデルで、すねの下のほうをどこまで「くつ」に含めるか（ハイカットのくつを焼き込んだキャラがいるか、で変わる）
- ショップのアイコンの大きさ、図鑑の並べ方の細かいところ
- 色の微調整（見本の色から大きく変えない）

## 7. 確かめること
- 新しいプレイヤーと、前からあるプレイヤーの両方で、ショップ→買う→つかう→プレイ で色が変わる
- 左右ちがい2足で、プレイ中に左右の色がちがって見える（右手・左手のワザの両方で）
